# DriveMate 계정과 비밀번호

배포 웹의 계정은 DriveMate 전용 이메일·비밀번호를 사용한다. 로컬 PC에서 만든 계정, Google·AWS·현대 계정과는 별개다. 일반 사용자는 웹에서 회원가입 후 로그인할 수 있다. 문서 검색용으로 예약된 소유자 이메일은 공개 회원가입으로 만들 수 없으며 운영자가 준비한 기존 계정을 사용한다.

## 로그인 후 비밀번호 변경

계정 화면의 접힌 비밀번호 변경 영역에서 현재 비밀번호, 새 비밀번호, 새 비밀번호 확인을 입력한다. 새 비밀번호는 10~128자이며 현재 비밀번호와 달라야 한다. 서버 성공 응답 후 현재 기기를 포함한 모든 로그인 세션과 실시간 위치 연결·미사용 연결 티켓을 폐기한다. 새 비밀번호로 다시 로그인해야 하며 차량·백업·문서 접근 권한은 유지한다.

API는 `POST /api/v1/auth/password`이고 Bearer 인증과 `current_password`, `new_password` 두 필드만 받는다. 성공 응답은 `{"ok":true,"reauthentication_required":true}`다. 현재 비밀번호 오류는 `400 invalid_current_password`, 같은 새 비밀번호는 `400 password_unchanged`, 입력 오류는 422, 요청 제한은 429다. 계정별 15분 5회와 접속 IP별 1분 30회로 제한하며 실패한 시도도 계산한다.

비밀번호 해시는 기존 PBKDF2-HMAC-SHA256 600,000회 방식과 새 무작위 salt를 사용한다. 계정 행 잠금 안에서 현재 비밀번호 확인·해시 교체·모든 세션 삭제를 한 트랜잭션으로 처리한다. 로그인도 같은 행 잠금 안에서 검증하고 세션을 생성하므로 변경 직전의 옛 비밀번호 검증이 뒤늦은 유효 세션을 남기지 않는다.

## 준비된 소유자 계정의 최초 설정

초기 운영 비밀번호를 사용자에게 파일·채팅으로 전달하지 않는다. 이 저장소의 `infra/aws/setup_owner_password.py`는 사용자가 직접 연 WSL 터미널에서 새 비밀번호를 두 번 마스킹 입력받는 도우미다. **운영 계정의 실제 변경은 사용자가 아래 명령을 직접 실행할 때만 발생한다.**

```bash
# make_drive_mate 저장소 디렉터리에서, 사용자가 직접 실행
python3 infra/aws/setup_owner_password.py
```

도우미는 고정된 배포 HTTPS 주소의 인증서·공개 DNS·Spring health를 먼저 확인한다. 이후 기존 로컬 초기 계정 파일의 값을 프로세스 메모리에서만 로그인에 사용하고, 사용자가 입력한 새 비밀번호로 변경한다. 새 로그인과 계정 일치 여부를 확인한 뒤 확인용 세션도 종료한다. 리디렉션과 환경 프록시를 사용하지 않고 비밀번호·토큰·응답 본문을 출력하지 않는다.

기본 초기 파일은 저장소의 형제 폴더 `FE-test/backend/data/deployment/app-secret.json`이다. 공개 clone에는 이 파일이 없으므로 일반 사용자가 실행하는 복구 수단이 아니다. 기존 파일이 다른 위치라면 `--initial-config`에 그 파일의 경로만 지정할 수 있으며 서버 주소나 비밀번호를 명령 인자로 받지 않는다.

성공 후 **초기 파일에 남은 이전 비밀번호는 무효**다. 도우미는 그 파일을 수정하거나 새 비밀번호를 저장하지 않는다. 이후 초기 비밀번호에 의존하는 운영 점검은 재사용하지 말고 별도 승인된 테스트 계정·로그인 절차로 바꿔야 한다. 소유자도 새 비밀번호를 잊으면 공개 이메일만으로 재설정할 수 없으며 운영자 확인이 필요하다. 이메일 소유권 확인이나 메일 기반 복구는 이 변경에 포함되지 않는다.

요청 중 통신이 끊기면 변경 적용 여부가 불확실할 수 있어 도우미는 자동 재시도하지 않는다. 웹에서 새 비밀번호로 확인하고, 확인 세션 정리를 검증하지 못했다는 안내가 있으면 운영자에게 세션 종료를 요청한다. 비밀번호나 계정을 삭제·재가입하여 문제를 해결하지 않는다.

## 검증 범위

관련 테스트는 임시 H2 계정과 합성 비밀번호만 사용한다. 인증 필요·현재 비밀번호 확인·입력 제한·요청 제한·모든 세션 폐기·예약 이메일 보호·동시 로그인 경합을 검사한다. CLI 테스트는 네트워크와 사용자 입력을 대체하여 출력 비노출·초기 파일 불변·세션 종료·리디렉션/비공개 DNS 거부를 검사한다. 실제 소유자 비밀번호를 자동 변경하거나 테스트를 위해 읽지 않는다.
