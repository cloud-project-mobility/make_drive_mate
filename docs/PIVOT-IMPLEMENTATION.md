# DriveMate 가치·매도 시점 목업 구현

기준일: 2026-11-02. 이번 변경은 외부 API 키 없이 실행되는 프런트엔드 목업이다. 실거래 자료로 학습한 모델, 제조사 API 연결, 시세 조회 서비스, 새로운 백엔드 엔드포인트는 구현하지 않았다.

## 실행과 화면

```sh
npm ci
npm run web -- --port 8081
```

`예시 차량으로 둘러보기` → `가치 분석` 홈에서 차량을 선택한다. 현재 가정 가치·미래 곡선·0/6/12/24개월 시나리오·보유비용 구성이 표시된다. `분석 조건 바꾸기`에서 값을 수정하고 `이 조건으로 다시 비교`를 누르면 결과가 바뀐다. 시나리오 카드를 누르면 해당 시점의 감가와 유지비 구성을 볼 수 있다. `계산 가정과 데이터 상태`에 수식과 제한을 공개한다.

기존 차량 등록·정비 기록·이동 계획·GPS·백업 흐름은 홈 하단과 기존 탭에 유지했다. 분석 폼은 화면 메모리만 사용한다. 차량 선택/등록은 기존 `useApp`의 검증된 액션을 사용하고, 분석 입력은 등록 차량이나 `AppState`/backup v1 계약을 변경하지 않는다. 차량 선택 변경, 차량 정보 변경, 새로고침에는 분석 예시값으로 돌아간다.

입력 단위는 가격·비용이 **만원**, 거리는 **km**, 기간은 **개월**이다.

| 입력                                     | 검증 범위 / 의미                                                                                   |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `modelYear`                              | 정수 2006~2026                                                                                     |
| `odometerKm`                             | 0~300,000                                                                                          |
| `originalPriceManwon`                    | 가상 기준가 100~30,000; 실제 신차가 조회 결과가 아님                                               |
| `monthlyKm`                              | 0~10,000                                                                                           |
| `monthlyUpkeepManwon`                    | 0~500; 감가를 제외한 보험·세금·정비·연료 등의 사용자 가정                                          |
| `minimumHoldMonths`                      | 0 / 6 / 12 / 24                                                                                    |
| `holdingBudgetManwon`                    | 0~10,000; 지금부터 매도까지의 누적 추가 보유 비용 한도                                             |
| `targetSaleManwon`                       | 0~30,000; 목표 최소 매도가                                                                         |
| `historyKnown`                           | 불리언; UI에서는 `무사고·비침수 가정` 또는 `이력 미확인`                                           |
| `recentQuoteManwon?`, `recentQuoteDate?` | 선택적 사용자 견적. 금액 100~30,000, 날짜는 기준일 이전 30일 이내. 두 값 모두 입력하거나 모두 생략 |

빈 문자열·부분 숫자·NaN·Infinity·음수·지원 범위 밖 입력은 계산하지 않는다. 폼 오류에는 마지막으로 적용한 조건의 결과임을 표시한다.

결과 `source`는 `'synthetic' | 'input-quote'`, `modelVersion`은 `'synthetic-rules-v1'`다. 각 시점은 매도 날짜, 주행거리, 기준값/하한/상한, 감가/유지비/합계, 조건 충족 여부와 미충족 이유를 제공한다. 제안은 `candidate | conditional | deferred` 및 `month: 0 | 6 | 12 | 24 | null`이다. 미래 API가 이 계약을 채택할 수 있지만 현재 계산은 로컬 함수 호출이다.

## 계산 규칙

```text
t = 0, 6, 12, 24
age(t) = 2026 - modelYear + t/12
km(t) = odometerKm + monthlyKm × t
F(t) = originalPriceManwon
       × 0.84^min(age(t), 1)
       × 0.90^max(age(t)-1, 0)
       × exp(-km(t)/400000)

견적 없음: V(t) = F(t)
견적 있음: V(t) = recentQuoteManwon × F(t)/F(0)

감가(t) = V(0) - V(t)
유지비(t) = monthlyUpkeepManwon × t
추가 보유 비용(t) = 감가(t) + 유지비(t)
가정 변화 범위(t) = V(t) × [1 ± (0.08 + 0.02 × t/12)]
```

등록월이 없어 차령은 연식 차이로 근사한다. 차량 등록 문자열의 마지막 연도 형태 토큰에서 연식을 추정하므로 화면에서 확인하도록 안내한다. 연식이 없거나 지원 범위 밖이면 계산하지 않고 입력창을 연다. 모든 차종에 같은 합성식을 적용하며, 이 계수와 범위는 실측 검증 결과가 아니다. 범위는 통계적 신뢰구간이나 정확도 지표가 아니다. 견적 입력 시 `입력 견적 기준 · 미래는 가정`으로 표시하고, 견적 가격을 현재 기준값으로 고정한다. 견적일부터 기준일까지의 가격 변동은 반영하지 않으며, 입력 견적의 진위나 거래 성립도 확인하지 않는다. 견적 모드에서는 F(t)/F(0)의 비율 때문에 기준가·초기 누적km·1년 이상 차령의 초기 수준 효과가 상쇄된다. 입력 견적과 앞으로의 월 주행량이 중심인 공통 감가 시나리오이며 차량별 학습 모델이 아니다.

조건 `t ≥ 최소 보유 기간`, `추가 보유 비용 ≤ 누적 한도`, `V(t) ≥ 목표 매도가`를 모두 만족하는 **가장 늦은 네 비교 시점 중 하나**를 제안한다. 연속적인 최적 매도일이나 가격 최대화를 계산하지 않는다. 후보가 없거나 이력 미확인이면 `deferred`다. 선택 후보의 낮은 가격 가정이 목표 매도가를 밑돌거나, `V(0) − 후보 하한 + 유지비`가 한도를 넘으면 `conditional`이다. 0개월에는 추가 보유 기간이 없으므로 비용은 0이며 비용 위험 검사에서도 제외한다.

사용자가 더 오래 사용하는 편익을 판단하도록 `6→12개월 추가 비용 / 6`도 표시한다. 매각 수수료·대출 이자·대체 차량 구매비는 계산하지 않으므로 교체의 총경제적 이익을 의미하지 않는다.

## 재현 가능한 기본 예시

아반떼 2023년식, 48,250km, 가상 기준가 3,000만원, 월 1,000km, 월 유지비 15만원, 최소 보유 6개월, 누적 비용 한도 700만원, 목표 매도가 1,400만원, 무사고·비침수 가정, 입력 견적 없음.

| 비교 시점 | 가정 가치 |  가정 변화 범위 | 추가 보유 비용 | 조건                       |
| --------- | --------: | --------------: | -------------: | -------------------------- |
| 지금      |   1,809.3 | 1,664.5~1,954.0 |              0 | 최소 기간 미달             |
| 6개월     |   1,690.9 | 1,538.7~1,843.0 |          208.4 | 충족                       |
| 12개월    |   1,580.2 | 1,422.2~1,738.2 |          409.0 | 충족 · 마지막 후보         |
| 24개월    |   1,380.1 | 1,214.5~1,545.8 |          789.1 | 비용 한도 초과·목표가 미달 |

단위: 만원. 화면은 가독성을 위해 정수로 표시한다. 도메인 출력은 소수 첫째 자리로 반올림하여 개별 항목의 차이·합계에 반올림 차이가 있을 수 있다. 6→12개월 추가 사용 비용은 월평균 약 33.4만원이다.

## 검증 기록

- `npm run check`: TypeScript, ESLint, 도메인 테스트 **71개 통과**.
- `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npx playwright test tests/e2e/valuation.spec.ts tests/e2e/app.spec.ts --workers=3`: 1차 desktop/mobile **28개 통과**. 연식 미기재 처리 검증을 추가한 최종 `valuation.spec.ts`는 **12개 통과**했다. 기존 `app.spec.ts` 18개와 합쳐 30개 시나리오를 검증했다. 입력 변화, 제약·이력 유보, 견적 날짜 검증, 원래 차량 정보 보존, 재시작 초기화, 기존 주행·정비·백업, 360px 레이아웃을 포함한다.
- 이 기록은 브라우저 검증이며 iOS/Android 실기기 검증을 의미하지 않는다. 실제 데이터에서 MAE·MAPE·구간 적중률·추천 성과를 측정한 결과도 없다.
