# DriveMate 백엔드 실행

FastAPI와 SQLite로 로컬 계정, 계정별 백업, 장소·경로·일정·차량 상태 조회를 연결합니다. 기본 외부 데이터 모드는 `mock`이며, 실제 Google·Kakao·현대 계정 연결 성공을 뜻하지 않습니다. API 키 없이 아래 시연과 테스트를 실행할 수 있습니다.

## API 키 없이 실행

Python 3.11 이상과 `uv`가 필요합니다. 저장소 루트에서 실행합니다. 최초 의존성 설치에는 패키지 다운로드가 필요할 수 있습니다.

```sh
cd backend
uv sync --locked
DRIVEMATE_PROVIDER_MODE=mock uv run --no-env-file --locked uvicorn app.main:app --host 127.0.0.1 --port 18085 --no-access-log
```

다른 터미널에서 상태를 확인합니다.

```sh
curl --fail http://127.0.0.1:18085/api/v1/health
```

응답의 `status`는 `ok`, `provider_mode`는 `mock`이어야 합니다. API 문서는 <http://127.0.0.1:18085/docs>입니다. 18085 포트를 다른 프로그램이 사용하면 그 프로그램을 확인하고 충돌을 해결합니다.

프런트엔드는 **저장소 루트의 별도 터미널**에서 시작합니다. Node.js 22.13 이상이 필요합니다.

```sh
npm ci
npm run web -- --port 8081
```

<http://127.0.0.1:8081>에서 앱을 열고 다음 순서로 시연합니다.

1. **예시 차량으로 둘러보기 → 설정**에서 서버 주소 `http://127.0.0.1:18085`를 확인하고 **서버 연결 확인**을 누릅니다.
2. `student@example.test` 같은 테스트 이메일과 10자 이상의 테스트 비밀번호로 **로컬 테스트 계정 만들기**를 누릅니다. 이메일 발송이나 Google 로그인이 아닙니다.
3. **서버 백업 확인 → 현재 기기 데이터를 서버에 저장 → 서버에 저장 확정**으로 백업을 저장합니다. 복원도 확인 화면을 거칩니다.
4. **이동 계획 → 일정으로 계획 → 서버 캘린더 일정 불러오기**에서 예시 회의를 선택합니다. 출발지 `서울역`, 도착지 `서울시청`을 검색한 뒤 각 검색 결과를 선택하고 **서버 경로 시간 적용**을 누릅니다.
5. 종일 일정은 도착 시간을 비워 두고 직접 입력하도록 안내하는지, 장소 없는 일정은 도착지를 직접 입력하도록 안내하는지 확인합니다.
6. **내 차량 → 차량 정보 수정 → 서버 예시 차량 상태 확인**에서 예시 배터리·주행 가능 거리와 시각 안내를 확인합니다. 기존 누적 주행거리가 바뀌면 안 됩니다.

mock 경로는 **서울역↔서울시청**과 **서울역↔강남역**만 지원합니다. 각각 합성 거리·시간은 2,400m/480초, 12,500m/1,800초입니다. 실제 도로나 교통 측정값이 아닙니다. 다른 구간은 오류를 반환하며 임의의 예상 시간으로 대체하지 않습니다.

## 검증 명령

`backend/`에서 실행합니다. Python 테스트는 외부 소켓 연결을 차단하고 임시 DB, 합성 데이터, `httpx.MockTransport`를 사용합니다.

```sh
uv run --no-env-file --locked pytest --cov=app --cov-branch --cov-fail-under=90
uv run --no-env-file --locked ruff check .
uv run --no-env-file --locked ruff format --check .
```

프런트엔드 검사와 실제 **로컬 서버 HTTP** 연동 검사는 저장소 루트에서 실행합니다. 통합 검사 스크립트는 18086 포트에 별도 mock 서버와 임시 DB를 만들고 종료 시 정리합니다. 18085 포트의 시연용 계정·백업을 사용하지 않습니다.

```sh
npm run check
npm run test:integrated -- tests/e2e/backend.spec.ts --workers=1
npm run export:web
```

Playwright 브라우저가 없다면 `npx playwright install chromium`으로 설치합니다. `npm run test:integrated`만 실행하면 기존 앱 시나리오를 포함한 전체 브라우저 검사를 수행합니다. CI는 Python 3.11·3.14의 백엔드 검사와 branch coverage 90% 이상, 통합 브라우저 검사, 모든 플랫폼의 Expo export를 요구합니다.

이미 실행 중인 18085 서버를 직접 검사하려는 경우에만 다음 명령을 사용합니다. 이 경우 테스트 계정·백업이 해당 DB에 저장됩니다. 개인 자료가 없는 시연용 DB를 사용하세요.

```sh
DRIVEMATE_BACKEND_URL=http://127.0.0.1:18085 npm run test:e2e -- tests/e2e/backend.spec.ts --workers=1
```

`npm run test:e2e`를 직접 실행하면서 `DRIVEMATE_BACKEND_URL`을 생략하면 백엔드 브라우저 테스트는 **건너뛰므로 연동 검증으로 집계하면 안 됩니다**.

## 데이터와 연결 범위

- DB 기본 위치는 `backend/data/drivemate.sqlite3`입니다. 서버를 다시 실행해도 계정과 백업은 유지됩니다. `DRIVEMATE_DATABASE`로 다른 파일을 지정할 수 있습니다.
- 서버 백업은 사용자가 저장·복원하는 스냅샷입니다. 다른 기기의 변경을 자동 병합하지 않습니다. 내용이 다른 오래된 버전 업로드는 HTTP 409이며, 동일 내용 재전송은 버전을 중복 증가시키지 않습니다.
- 주행 중이거나 위치 권한을 요청하는 동안 프런트엔드 백업 저장·복원을 제한합니다. 서버도 진행 중인 주행을 포함한 백업을 거부합니다. 복원 전에 기존 출발 알림을 취소하고, 필요한 알림은 사용자가 다시 켭니다.
- 서버 세션은 프런트엔드 메모리에만 둡니다. 새로고침·앱 재시작 후 다시 로그인합니다. 계정을 바꾸거나 로그아웃해도 기기 기록은 유지되므로 업로드 전에 내용을 확인합니다.
- Google 토큰 재발급은 같은 DB·계정의 동시 요청을 한 서버 프로세스 안에서 직렬화합니다. 일정 조회가 인증 오류(401)를 받으면 한 번 재발급해 재시도하고, 동의 만료나 재시도 후 인증 실패는 해당 연결만 해제합니다. 권한 오류(403)·일시 장애는 연결을 보존합니다. 현재는 기본 명령처럼 **worker 한 개**로 실행하세요. 여러 프로세스에서의 동시 재발급은 지원하지 않으며, DB의 버전 비교는 변경된 연결을 덮어쓰는 것만 막습니다.
- 이동 계획의 선택 좌표와 경로 출처·계산 시각, 완료한 주행의 원본 계획 ID를 백업에 보존합니다. 예전 백업에 이 필드가 없어도 복원할 수 있습니다. 백업과 계정 입력의 문자열 최대 길이는 프런트엔드와 서버 모두 JavaScript의 UTF-16 단위로 검사합니다.
- `.env`는 앱에서 자동으로 읽지 않습니다. [.env.example](.env.example)은 빈 설정 목록이며, mock 실행에는 복사하거나 채울 필요가 없습니다. mock 모드는 외부 API 비밀값 환경변수도 사용하지 않습니다.

실제 기기에서 PC 서버를 연결하려면 기기의 `127.0.0.1`이 PC를 가리키지 않는다는 점을 고려해야 합니다. 같은 사설망에서 테스트할 때만 서버의 수신 주소와 앱의 PC 주소를 맞추세요. 이 문서의 루프백 시연과 웹 테스트는 실기기 GPS·알림·백그라운드 동작 검증을 대신하지 않습니다.

API 목록, 설계 근거, 향후 필요한 설정은 [백엔드 인계 문서](../docs/BACKEND.md)에 모았습니다.
