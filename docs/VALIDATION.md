### 백엔드와 실제 HTTP에서 확인한 항목

- 계정별 자료 분리, 비밀번호 해시·세션 만료·로그아웃·계정 삭제, 요청 제한과 입력 오류를 확인했다. 원본 비밀번호·토큰·공급자 오류 본문을 오류 메시지에 포함하지 않는다.
- 백업은 버전 조회 후 저장하며, 다른 내용의 오래된 버전은 409로 거부한다. 동일 내용 재전송은 버전이나 주행거리를 중복 증가시키지 않는다. 완료되지 않은 주행·잘못된 차량 참조·손상된 형식은 서버가 거부한다.
- Google OAuth는 state·PKCE·계정별 암호화 보관·갱신·연결 해제·회수된 권한·정확한 읽기 scope를 주입 transport로 검사했다. 실제 사용자 동의나 Google 접근 성공을 확인한 것은 아니다.
- Calendar의 종일 제외 종료일, 장소 누락, 시간대·잘못된 offset, 반복 일정 목록·빈 중간 페이지·페이지 토큰 반복을 확인했다. Kakao는 HTTP 성공과 경로 결과 코드, 원본 m/s 단위, 타임아웃·429·잘못된 응답을 구분했다.
- 현대 예시는 원본 거리 단위와 시간대 미확인 제조사 시각, UTC 수신 시각을 분리했다. 차량 상태 조회로 기존 누적 주행거리가 변경되지 않는다.

`backend/scripts/verify_restart.py`는 18087 포트에 임시 DB를 사용하는 별도 uvicorn 프로세스를 만든다. **HTTP 계정 생성·백업 commit → 프로세스 강제 종료 → 동일 DB로 재시작 → 백업·세션 유지 → 중복 재전송 유지 → 다른 내용의 오래된 저장 거부 → 계정 삭제 후 세션 거부**를 확인하고 5개의 PASS를 출력했다. DB 연결 객체만 다시 여는 테스트와 별도의 프로세스 재시작 근거다.

```sh
cd backend
uv run --no-env-file --locked python scripts/verify_restart.py
```

`npm run test:integrated`는 18086 포트에 임시 DB와 mock API를 시작해 브라우저에서 실제로 계정·백업 저장/복원·일정 선택·경로 계산·예시 차량 상태를 사용한다. 서버 종료 시 임시 자료를 정리한다. `npm run test:e2e`를 직접 실행하면서 `DRIVEMATE_BACKEND_URL`을 생략하면 백엔드 사례는 건너뛰므로, 그 결과만으로 연동 성공을 주장하지 않는다.

최종 화면 수정 후 `npm run check`와 `npx expo export --platform all`을 다시 통과했다. 개발 서버를 종료하고 다음 정적 서버를 실행한 상태에서 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:integrated`로 같은 40개 시나리오를 모두 재검증했다. CI처럼 Playwright가 Chromium을 설치한 환경에서는 실행 파일 환경변수가 필요 없다.

```sh
npx --yes serve@14 dist --listen tcp://127.0.0.1:8081 --single --no-request-logging --no-clipboard --no-port-switching
```

### 의존성 점검과 URI 디코더 변경

현재 잠금 파일의 `npm audit --json`은 **8개 패키지 경고: 높음 3, 낮음 5, 보통·치명적 0**을 보고한다. 같은 원인이 상위 패키지로 전파된 개수를 포함한다. [2026-10-28 원자료](evidence/2026-10-28/dependency-audit.json)를 별도 보관했으며, 아래 2026-10-21의 28개 경고 자료를 덮어쓰지 않았다. 경고가 남아 있으므로 의존성 보안 검사에 모두 통과했다고 표시하지 않는다.

남은 직접 원인은 `zod`와 `deepmerge`이며 확인된 경로는 Expo CLI·설정·Metro 설정·네이티브 프로젝트 생성 도구다. 이 결과만으로 모든 실행 환경에서 영향이 없다고 단정하지 않는다. npm의 자동 수정 제안에는 Expo **51.0.39**로의 호환성 파괴 변경이 포함되어 그대로 적용하지 않았다.

라우터가 사용하는 URI 디코더는 수정된 upstream **0.5.1**의 소스를 MIT 라이선스와 함께 `vendor/decode-uri-component/`에 보관하고 CommonJS 호환 형태로 연결했다. 변경은 `module.exports`와 기존의 리터럴 `+` 처리 유지이며, 패키지 버전은 `0.5.1+drivemate.cjs.1`이다. `npm ci` 새 설치에서 로컬 의존성을 해석하는지 확인했고, 실제 `query-string` 소비 경로·한글·잘못된 UTF-8·중복 디코딩 방지·큰 잘못된 입력의 제한 시간 회귀를 검사했다. [변경 근거·라이선스·제거 조건](../vendor/decode-uri-component/README.md)을 함께 보관한다. 이 변경으로 별개의 Zod·deepmerge 경고까지 해결됐다고 주장하지 않는다.

### 과제 시연 완료와 운영 검증의 구분

키 없는 과제 시연의 기준은 로컬 계정, 버전이 있는 서버 백업, 명시적 예시 일정·장소·경로·차량 상태가 기존 차량·주행·점검 흐름과 연결되는 것이다. 자동 테스트·실제 로컬 HTTP 검사·최종 브라우저 실행 근거를 이 기준으로 확인한다. 실제 서비스 계정으로 데이터가 연결되는지는 별도 완료 조건이며 [요구사항/인계 표](BACKEND.md)에 남은 내용을 기록한다.

`adb devices`에서 연결된 Android 단말이 없어 네이티브 실기기 시험을 수행하지 않았다. iOS 실기기 GPS·OS 알림·잠금/복귀·서명·스토어 배포도 확인하지 않았다. Google/Kakao의 실제 권한·호출, 현대 실차 인증·소유 동의·계약·데이터 최신성은 미검증이다. 실제 키가 없어도 테스트 가능한 구현 범위와, 키·동의·기기가 있어야 확인할 범위를 분리해 발표한다.

## 2026-10-21 · 이전 프런트엔드 검증 기록

아래는 당시 결과를 보존한 역사적 기록이다. 현재 백엔드 통합 이후의 테스트 수·의존성 경고·실연동 상태를 나타내지 않는다.

검증일: 2026-10-21. Penpot 원안의 17개 화면을 조사하고 원본 자산·화면·텍스트를 보관했다. 아래 결과는 자동 검증과 화면 점검 결과이며 실제 사용자를 모집한 사용성 연구는 아니다.

### 실행 환경과 범위

- 로컬: Linux, Node 26.5.1 / npm 12.0.2, Expo SDK 57, 시스템 Chromium.
- CI: Ubuntu, Node 24, Playwright Chromium. `.github/workflows/quality.yml`에 정의.
- 화면: 데스크톱 1440px, 모바일 390px 및 좁은 360px. 앱 UI는 React Native 컴포넌트로 작성.
- 도메인·비동기 위치 구독 단위 테스트 **19개 통과**.
- TypeScript strict 검사와 ESLint 통과, Expo Doctor **21/21** 통과.
- `expo export --platform all`: 웹 JS 및 Android/iOS Hermes 번들 생성 성공. 서명된 네이티브 설치 파일을 빌드하거나 실제 단말에서 시험했다는 의미는 아니다.

### 검증한 사용자 흐름

`tests/e2e/app.spec.ts`는 실제 UI 조작으로 다음을 확인한다. 데스크톱과 모바일에서 각각 실행한다.

1. 예시 차량 선택 후 이름·주행거리 일치, 전기차에서 엔진 항목 제외.
2. 빈 차고 등록, 잘못된 입력 거부, 재실행 복원, 3대 상한.
3. 현재 거리보다 높은 정비 기록·미래 정비일 거부, 유효한 기록 저장·복원.
4. 자정을 넘는 일정의 전날 출발 시간, 저장·재실행 후 값 유지.
5. 브라우저에서 실제로 위치 권한을 거부했을 때 복구 안내, 거짓 기록 상태 없음.
6. 360px 및 데스크톱 가로 넘침과 주요 버튼 44px 이상.
7. 시간 설정 범위 검증·저장·다음 계획 반영, 연결되지 않은 서비스 표시.
8. 제어된 좌표로 GPS 시작·정지·페이지 재실행·재개·저장. 정지 중 이동 제외, 차량 누적 거리에 1회 반영.
9. 실제 JSON 다운로드, 잘못된 백업 거부, 내용 확인 후 복원·재실행.

`tests/e2e/recovery.spec.ts`는 오류를 의도적으로 주입한다. 첫 시작 전 직접 링크를 열어도 데이터가 고립되지 않는지, 손상 원본을 내보내고 확인한 뒤 백업·초기화하는지, 저장 실패가 표시되고 최신 상태를 재시도하는지 확인한다.

위치 기록 테스트는 브라우저 위치 이벤트를 통제한다. 실제 GPS 센서 품질·터널·장거리 운전·배터리 영향은 검증하지 않았다. iOS/Android 권한 창, OS 알림 전달, 백업 공유 대상 앱은 실기기 출시 검증이 필요하다.

`tests/e2e/recorder-errors.spec.ts`는 위치 오류 시 일시 정지, 정확한 browser watch ID 해제, 재개 후 지연된 이전 콜백 무시를 검증한다. 저장 데이터의 enum 타입과 초기 진입 조건, 이전 네이티브 구독의 늦은 성공·실패는 단위 테스트로 함께 검증했다.

### 접근성과 화면 점검

`npm run web`을 실행한 상태에서 다음 명령으로 접근성 검사를 재현할 수 있다.

```sh
npm run test:a11y
# 시스템 Chromium을 사용할 경우
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:a11y
```

최종 화면 24개 위치를 스크롤하며 WCAG 2 A/AA·2.1 A/AA 규칙을 검사해 자동 탐지 위반 0건, 콘솔 오류 0건을 확인했다. [원자료](evidence/accessibility-axe.json)와 [데스크톱](evidence/implementation-desktop.png)·[모바일](evidence/implementation-mobile.png) 화면을 보관했다. 초기에 발견한 글자 대비, 탭 역할, 버튼 이름, 빈 문자열 렌더링 오류, 모바일 화면 아래로 밀리는 확인 동작을 수정했다. 자동 도구는 수동 스크린 리더·키보드·확대·기기 검증을 대신하지 않는다.

### 의존성 점검

설치 잠금 파일을 대상으로 `npm audit --json`을 실행했다. **28개 패키지 경고(높음 18, 보통 10)**가 있으며 같은 원인이 상위 패키지에 전파된 개수를 포함한다. 이는 보안 검사 통과 결과가 아니다. [원자료](evidence/dependency-audit.json)를 보관했고 CI에서도 별도 경고 보고서를 남긴다.

직접 원인은 `braces`, `node-forge`, `decode-uri-component`, `uuid`의 공지다. 앞의 두 패키지는 점검 당시 npm 최신 배포도 영향 범위에 있었다. npm이 제안하는 일부 자동 수정은 Expo 44/React Native 0.72로 내려가는 호환성 파괴 변경이며 적용하지 않았다. 나머지의 메이저 버전 강제 교체도 Expo 내부 CommonJS/ESM 호환성 검증 없이 적용하지 않았다. 주로 번들러·서명·네이티브 프로젝트 생성 도구 경로이지만 URI 디코더는 라우터에도 연결되므로 모두 개발 전용이라고 단정하지 않는다. 배포 전 SDK 상위 버전·업스트림 패치와 영향도를 다시 검토해야 한다.

### 남은 운영 검증

Google 로그인·캘린더·실시간 길찾기·차량 API·서버 동기화는 현재 연결하지 않았다. UI에 연결되지 않았다고 표시하고 [연동 경계](INTEGRATION.md)에 필요한 계약을 정리했다. 실기기 GPS·알림·잠금/복귀, 네이티브 키보드·안전 영역, 앱 서명·배포, 실제 사용자 과제 수행 시간은 별도 검증 대상이다.
