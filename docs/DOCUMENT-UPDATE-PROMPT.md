## 1. 근거와 작업 원칙

- 실제 실행 산출물·평가 JSON·최신 코드 및 검증 기록을 사실 확인의 우선 근거로 사용해 줘. 설명 문서와 원본 사이에 충돌이 있으면 충돌표를 만들고 확인 가능한 범위만 수정해 줘.
- 모든 주요 기능을 `구현·로컬 검증됨`, `운영 미배포/원격 미실행`, `계획/향후 과제`로 구분해 줘. 코드 존재만으로 배포 성공·정기 작업 완료·사용자 효과 검증을 주장하지 마.
- 현재 AWS 공개 URL·실행 중인 EC2·RDS·주간 작업은 없다. 실패 자원을 정리한 **미배포 상태**를 단순한 상태 확인 대기로 흐리지 마. CI/CD 원격 실행과 실제 과금 결과도 미검증 범위로 구분해 줘. 가짜 URL, 스크린샷, 로그, 실험 표본, 인용 문헌을 만들지 마.
- 기존 원본을 덮어쓰지 말고 수정본을 별도 파일로 만들어 줘. 기존 제목 체계·필수 제출 항목·표 양식·발표 디자인은 가능한 한 유지해 줘. 실제 파일 편집이 불가능하면 문서 위치별 교체 원고와 슬라이드별 완성 원고를 제공해 줘.
- 설명은 한국어로 쓰고, 기술 용어는 처음 등장할 때 짧게 풀어 줘. 지표는 단위·분모·평가 대상·한계를 같은 표 또는 바로 이어지는 문장에서 설명해 줘.
- 기존 차량 사진과 다른 사용자의 화면 변경은 보존하고 사진 출처를 유지해 줘. 제출자료에 API 키, 비밀번호, 허용 계정 이메일, 차량번호, 사용자 연락처, 내부 파일 경로를 넣지 마.

## 2. 프로젝트 목적을 다음처럼 정리해 줘

DriveMate는 차량 조건을 등록하고 공매 데이터에서 얻은 참고 가치, 예상 이용량에 따른 조건 변화, 사용자가 입력한 보유비용을 함께 비교하는 의사결정 지원 PoC다. 데이터가 부족한 차량에는 판단을 유보하고 이유를 보여준다. “지금 얼마에 팔 수 있는지 확정하고 최적 매도일을 보장하는 서비스”라고 소개하지 마.

서비스가 지향하는 경험과 현재 검증 범위를 구분해 줘. 사용자 관심사는 현재 가치·앞으로 더 탈 때의 비용·매도 검토 시점이지만, 현재 데이터의 목표값은 **온비드 공매 낙찰가**다. 소비자 소매 시세·딜러 매입가·개인 차량의 확정 거래가와 동등하게 취급하지 마.

미래 차령·주행거리만 바꾸는 결과는 **시장 조건을 고정한 조건부 시나리오**로 써 줘. 실제 미래 시세 예측, 인과적 감가율, 확정적인 최적 매도일로 부르지 마. 트리 모델의 계단형 결과·외삽 한계와 비단조 결과 가능성도 남겨 줘. 유지비는 사용자 입력 가정이며 정비비 자동 예측이나 완전한 총소유비용 최적화가 아니다.

## 3. 실제 데이터와 전처리

확인된 기준 실행은 다음과 같다. 새 실행 결과가 첨부되었다면 기준 실행과 섞지 말고 버전별 표를 작성해 줘.

- 원천: 공공데이터포털의 차세대 온비드 물건 입찰결과목록 서비스. 상세 API는 연결 가능성을 확인했으나 차량 상태·사고·정비 정보를 풍부하게 제공하는 것으로 과장하지 않는다.
- 기간: 2025-11-04~2026-11-03.
- 원본 5,268행, 승용 범주 2,284행, 최종 정제 2,197행.
- 날짜·연식·주행거리·금액 단위 정리, 이벤트 중복 검토, 결측·이상값 표시, 원천·제외 사유·해시 보존.
- 폐차/고철·점검용/테스트 물건·여러 대 묶음과 단위 불명확 물건은 원문 의미를 근거로 제외 또는 검토 대기로 구분한다. 높은 가격만을 이유로 시험 표본을 없애지 않는다.
- 사고·정비·침수·트림 등을 모르는 상태를 무사고나 정상으로 자동 대체하지 않는다. 원문에 없는 수리비·감가 라벨을 만들지 않는다.
- 원본 저장, 전처리, 훈련 전용 대체/인코딩, 시간순 평가가 어디에서 일어나는지 구분해 줘. 전체 데이터로 대체값이나 범주 규칙을 미리 학습하는 설명은 삭제해 줘.

## 4. ML 평가를 정확하게 교체해 줘

현재 모델은 검증 구간에서 선택한 **로그 가격 Random Forest**다. 비교 모델은 전체 중앙값, 차종·차령 구간 중앙값, Extra Trees, Random Forest다. GB/Gradient Boosting이 최종 선택되었다는 오래된 표현은 수정해 줘.

동일 차량이 시간 경계에 걸친 53개 그룹·122행을 제외한 뒤 훈련 839, 검증 559, 구간 보정 336, 최종 시험 341행을 사용했다. 모델 선택은 검증 자료로 하고 최종 시험 결과를 보고 모델을 고르지 않았다는 점을 설명해 줘.

성능 표는 반드시 아래 두 행을 함께 싣는다.

| 평가 대상 | 표본 수 | 평균 절대오차(MAE) | 해석 |
|---|---:|---:|---|
| 전체 최종 시험 | 341건 | 236.15만원 | 전체 시험 자료 결과 |
| 사전에 정한 가격 제공 조건을 충족한 자료 | 262건 | 134.74만원 | 제공률 76.83%, 79건 유보. 전체 성능의 대체 지표가 아님 |

MAE를 정확도 백분율로 바꾸거나 “평균 134만원 오차로 모든 차량을 예측한다”고 쓰지 마. 모델별 검증 오차를 넣을 경우 실제 근거의 값(전체 중앙값 206.05, 차종·차령 중앙값 201.17, Extra Trees 168.84, Random Forest 153.11만원)을 사용하고 최종 시험 MAE와 구분해 줘.

미학습 모델·제조사 조합이나 핵심 수치의 훈련 범위 이탈은 가격 유보 사유다. 같은 모델 표본이 10건 미만이라는 조건만으로는 경고를 표시하며 자동 유보하지 않는다. 수용 기준·흐름도에서 경고와 유보 분기를 섞지 마. 수치 범위 안의 모든 조합이 충분히 검증됐다고도 쓰지 마.

참고 구간은 오차 보정 자료로 만든 범위다. 미래 시장가격의 80% 신뢰 보장으로 쓰지 마. 전체 시험의 참고 구간 포함률 76.83%와 가격 제공률 76.83%는 우연히 값이 같은 **서로 다른 지표**이므로 표 제목·분모를 명확히 구분해 줘. 세부 지표가 필요하면 최신 `metrics.json`을 확인해 줘.

## 5. LLM과 RAG를 구별해 줘

**가격 근거 설명:** ML/서버가 계산한 가격·참고 구간·유사 공매 사례·한계 중 GPT가 설명할 근거를 선택한다. GPT가 새 차량 가격이나 수익을 생성하지 않는다. 가격 숫자를 임의로 바꾸거나 근거 없는 정비·사고 사실을 보태지 않는다.

**프로젝트 문서 검색:** 차량 가격 모델과 별도 기능이다. 현재 코퍼스는 6개 문서, 83개 청크다. Word는 절/문단, PowerPoint는 슬라이드 위치를 보존한다. 렌더링하지 않은 Word 쪽 번호는 만들지 않는다. 저장소에 있는 승인된 사본을 사용하며 OneDrive를 실시간 동기화한다고 쓰지 않는다.

검색 구조는 다음과 같다.

`질문 → text-embedding-3-small(1536차원) → 코사인 검색 + 한국어 단어/문자 BM25 → RRF 결합 → 중복 절 정리 → 선택적 gpt-6-astra 근거 선택 → 원문 인용·출처·상태 표시`

현재 HTTP 시연은 `DRIVEMATE_RAG_BACKEND=local`을 명시한 로컬 벡터 검색이다. 기본값인 `pgvector`는 운영용 구현이며 실제 RDS 적재·SQL 검색은 아직 실행하지 않았다. 실패를 숨기기 위해 자동으로 local로 바꾸는 구조가 아니며, local HTTP 성공을 RDS 성공으로 쓰지 마.

계획 문서, 당시 보고 내용, 공식 출처, 현재 코드/실행에서 확인된 내용을 별도 상태로 표시한다. 과거 보고서의 FastAPI·부스팅·미구현 설명을 현재 사실처럼 인용하지 않는다. GPT는 검색된 출처 ID만 선택하고 앱은 검증된 원문을 보여준다. 원문 자체의 사실성·관련성을 완벽하게 보장하는 기능은 아니다.

RAG 결과는 다음과 같이 제한해서 보고해 줘.

- 개발자가 작성한 출처 정답 질문 10개: Recall@1 0.70, Recall@3 0.90, Recall@6 0.90, MRR@6 0.7667.
- 문서 밖 질문 3개: 실제 LLM 근거 선택에서 3/3 보류.
- 단순 유사도 게이트만으로는 위 3개가 모두 통과했다. 이 실패를 숨기지 않는다.
- 소형 개발 확인용 평가이며 독립적인 일반 검색 성능 평가가 아니다. “RAG 정확도 90%”, “환각 완전 방지” 또는 “100% 안전”으로 줄여 쓰지 않는다.
- 검색만 해도 임베딩 비용이 발생한다. 유료 기능 요청은 UTC 날짜 기준 서버 전체 하루 20회 한도를 공유하며, 요청 1회가 외부 API 호출 정확히 1회를 뜻하지 않는다.
- 원본 문서 접근은 승인 계정으로 제한하고 개인정보 가림 본문만 사용한다. 공개 데모 화면에 개인 문서 원본을 직접 다운로드하는 링크를 만들지 않는다.
- 허용 이메일의 공개 회원가입은 `RegistrationPolicy`가 403으로 거부한다. 관리자가 임시 bootstrap 토큰으로 최초 계정을 준비하고, 계정을 삭제해도 공개 재가입으로 문서 권한을 얻을 수 없다. 로컬에서는 최초 생성 뒤 토큰 제거·서버 재시작 및 일반 가입 403을 확인했다. AWS에서는 미실행이다. 이메일 소유권 확인 서비스를 구현했다고 바꾸어 쓰지 마.

## 6. 아키텍처와 운영 상태

현재 HTTP 서버는 **Spring Boot 4.1.2**다. Python은 ML·RAG·데이터 작업용 프로세스이며 FastAPI HTTP 서버를 우회 호출하는 구조가 아니다. Django로 표기하지 마.

다음 두 흐름을 별도 다이어그램으로 만들어 줘. 로컬 실행 완료·운영 미배포·향후 작업의 범례를 넣고, 검증 기록에 따라 각 노드의 상태를 표시해 줘.

1. 사용자 흐름: 차량 입력 → Spring 인증/검증 → Python ML 추론 → 지원 여부 판단 → 공매 가격·조건 시나리오 → 선택적 GPT 근거 설명. 프로젝트 문서 RAG는 옆의 독립 흐름으로 배치한다.
2. 반복 분석: EventBridge 주간 일정 → SQS → worker → 온비드 수집 → 비공개 원본 저장 → 전처리 → 후보 모델 평가 → 집계·시각화 게시 → 사람 검토. 운영 모델 자동 승격 화살표를 그리지 않는다.

현재는 loopback 웹 → Spring/H2 → Python ML·local RAG로 실행한다. 향후 배포 목표는 CloudFront HTTPS, EC2 Nginx/Spring, PostgreSQL RDS/pgvector, 비공개 S3, SQS/EventBridge다. 검증한 목표 유형은 c7i-flex.large(4 GiB)와 PostgreSQL 18.6 db.t4g.micro·Single-AZ·백업 보존 1일이다. 실패 배포에서 만든 RDS는 최종 암호화 백업 후 삭제했고 실패 스택·VPC·빈 작업 큐도 정리했다. 현재 공개 서비스는 없다. 별도 foundation의 비공개 S3·secret과 최종 백업·복원용 키는 남아 있다. Single-AZ를 Multi-AZ 또는 장애 무중단 구조로 그리지 마.

GitHub Actions CI/CD는 로컬 파일 준비와 어댑터 검사를 완료했다. 사용자가 지정한 공개 저장소 `cloud-project-mobility/make_drive_mate`의 main에 소스 312개 파일을 업로드했고 최초 통합 커밋 `8b8eea7484ebe8cf8f2dde10ab0f6737a1d5aa21`의 로컬·원격 일치를 확인했다. 원격 CI 워크플로 등록과 실제 실행 시작을 확인했다. 성공 여부는 [Actions 기록](https://github.com/cloud-project-mobility/make_drive_mate/actions)을 기준으로 하며 통과 기록이 확인되기 전에 성공했다고 쓰지 마. 기존 `FE-test`는 로컬 작업본의 기반이다. OIDC 신뢰 조건은 새 대상의 불변 저장소 식별자를 포함한 main 브랜치 subject로 맞췄다. 공개 저장소에는 원본 Office 문서·데이터·모델·RAG 본문/색인·키·계정 설정을 제외했다. 현재 AWS 실행 대상이 없어 CD는 활성화하지 않으며 CI 통과를 운영 배포 완료로 쓰지 마.

검증된 main 산출물을 선택해 배포하는 과정과 운영 모델 승격은 별개의 절차다. 월 20만원은 사용자 예산이며 실제 과금·무료 혜택·알림을 확인하기 전에는 고정 월 비용이나 무조건 무료라고 약속하지 마.

현재 로컬 Spring `mvn test`는 47개 테스트가 통과했다. 여기에는 허용 이메일 공개 가입·삭제 후 재가입 방어 검사 2개, 차량 카탈로그 검사 9개, 명시적 local RAG 설정 검사가 포함된다. 실제 로컬 HTTP 요청은 로그인 200, 예약 이메일 일반 가입 403, ML+GPT 200(7.77초), local RAG+GPT 200·answered(6.71초), 분석 집계 200을 확인했다. 시간은 각 1회 측정으로 일반 성능 보장이 아니다. RAG 단위 테스트 9개, CI 배포 어댑터 테스트 7개와 서로 다른 시험이다. 최신 통합 프런트는 추가 차량 카탈로그·서버 차량 화면을 포함해 타입·lint·90개 테스트와 웹 export(986개 모듈)를 통과했다. 초기 프런트 검증의 76개 검사 및 브라우저 34개 시나리오·관련 재검증 기록과 구분해 줘. 이 수치를 실제 사용자 평가 건수로 바꾸지 마.

Colab 노트북은 기존 Drive 파일 ID에 최신 669,524바이트로 갱신했고 재다운로드 바이트 일치를 확인했다. 현재 Colab 런타임에서 전체 셀을 실행한 사실은 확인하지 못했다. WSL에서 코드 9개 셀·내장 테스트 25개를 실행한 결과와 원격 파일 갱신을 분리해 써 줘.

## 7. 기존 서비스와의 차이

KB차차차 등 기존 플랫폼도 현재/미래 가치나 보유비용 기능을 제공할 수 있음을 전제로 써 줘. 최신 공식 근거가 없으면 특정 기능이 경쟁사에 없다고 단정하지 마. 비교표의 미확인 칸은 `공식 확인 필요`로 남겨 줘.

우리의 차별화는 시장 독점 기능이 아니라 이번 PoC에서 실제로 구현·검증할 선택으로 설명해 줘.

- 원천 가격의 종류와 표본·누락 정보·전체/조건부 오차를 공개하는 설명 방식.
- 같은 조건을 바꾸어 보유비용을 비교하고 충분한 근거가 없는 경우 이유와 함께 유보하는 흐름.
- 유사 공매 사례와 검증된 사실에 묶인 설명.
- 계획과 구현 상태를 구별하는 문서 근거 검색 및 재현 가능한 데이터 분석 기록.

현재 원천의 제약 때문에 한국 소비자 시세 정확도나 대형 플랫폼 대비 우월성을 검증했다고 쓰지 마. 문서 RAG를 이용자 전체가 요구하는 핵심 기능으로 단정하지 말고, 프로젝트 설명·운영 근거 확인용 보조 기능의 실제 용도를 밝힌다.

## 8. 문서별 결과물

**PoC 계획·설계서:** 문제와 가설, 데이터 계약, 전처리·누수 방지, 모델 비교·유보 기준, 설명/RAG 계약, 시스템 흐름, 접근 권한·비용 관리, 수용 기준, 위험·향후 계획을 현재 근거로 다시 정리해 줘. 완료된 실험과 앞으로 검증할 가설을 분리해 줘. 사용자 연구·실차 거래 검증을 수행하지 않았다면 완료처럼 쓰지 마.

**중간보고서:** 기존 제출 양식을 유지하고 목표 대비 현재 진척, 확보 데이터, 구현 범위, 시험 결과, 발견한 한계, 계획 변경 사유, 남은 일정·담당 과제를 정리해 줘. 각 완료 주장에 문서/코드/산출물/검증 기록을 연결하는 짧은 근거표를 넣어 줘. 계획된 참여자 수와 실제 참여자 수를 혼합하지 마.

**발표자료:** 원본 슬라이드 수와 디자인을 우선 유지하되 필요하면 최소한으로 재배치해 줘. 문제·데이터 확보·실제 흐름·모델 비교·전체/조건부 성능·유보와 조건 시나리오·LLM/RAG 역할·클라우드 구성·검증과 한계·차별화·향후 계획을 일관된 이야기로 연결해 줘. 한 슬라이드에 핵심 주장 하나를 두고 작은 수치에도 단위·분모·출처를 적어 줘. 실제 화면은 로컬 시연으로 표시하고 클라우드 도식에는 미배포 상태를 명시해 줘. 가짜 운영 캡처를 만들지 마. 각 슬라이드에 바로 읽을 수 있는 발표자 노트를 써 줘.

마지막으로 다음을 함께 제공해 줘.

1. 원본의 주장과 수정 문구·근거·이유를 연결한 변경표.
2. 세 문서의 수정본 또는 바로 붙여 넣을 수 있는 완성 원고.
3. 예상 질문과 근거 있는 답변: 공매가의 대표성, 큰 전체 오차, 부분집합 선택 편향, 실제 미래 시세와의 차이, 왜 Random Forest인가, GPT가 가격을 만들지 않는 이유, RAG의 소형 평가 한계, 경쟁 서비스와의 중복, 무료 플랜·가용성·비용 관리, 자동 재학습과 운영 승격의 차이.
4. 아직 근거가 없어 확정할 수 없는 항목 목록. 이를 추정으로 채우지 마.

작성 후 세 문서의 숫자·기술명·기간·상태·용어가 서로 일치하는지 대조해 줘. 특히 `236.15만원/341건`, `134.74만원/262건`, `제공률 76.83%`, `6개 문서/83개 청크`, `Recall@1 0.70·@3/@6 0.90`, `MRR@6 0.7667`이 서로 다른 지표로 정확하게 남아 있는지 확인해 줘.
