## Running configuration and follow-up operations

The verified route is **CloudFront → ALB → one ECS Fargate task with separate Nginx and Spring/Python containers**, sized at 1 vCPU and 3 GiB. The API replica count stays at one because live-location relay state is in memory. A separate cycle task consumes SQS once and exits; it is not a continuously running worker service. Its first on-demand execution and S3-to-public-API aggregate refresh succeeded. The hourly worker rule is enabled; an empty queue causes it to exit without a new collection. The separate weekly enqueue rule is also enabled with `cron(0 17 ? * SUN *)`, creating requests at Monday 02:00 KST. A weekly request's first scheduled consumer opportunity is 02:05 KST, subject to scheduling/capacity delays.

- Cleanup preserved the same RDS endpoint: database available, encrypted, deletion-protected, with one-day backups unchanged. The ECS service remains healthy with one running task.
- Observe the first scheduled execution and subsequent failures/retries; a successful initial run and enabled rule do not establish ongoing reliability. A completed cycle must not promote the service model.
- Kubernetes manifests have been rendered only. No Kubernetes cluster or Kubernetes deployment exists.
- The owner chose to complete [initial password setup](../../docs/ACCOUNT-ACCESS.md) later by entering a new password directly in the WSL helper. The helper has been prepared, but the live owner password has not been changed. The login UI also supports authenticated password changes; a successful change revokes all account sessions.
- The APK is an internal test build, not a store release. Same-account WebSocket location synchronization remains web-only and is not implemented in the native APK. Successful compilation and static APK checks do not establish emulator or real-phone behavior.

The first API cycle used schema `onbid-api-v1` and the event-date range 2025-11-04 through 2026-11-03: 5,268 raw rows, 2,284 passenger-category rows, 2,187 clean rows and 3,081 total excluded rows. It reported 154 repeated-vehicle groups, 13 API calls and zero outstanding request reservations. S3 latest and completion markers use AES256 encryption. These 2,187 rows are a new cycle result, separate from the serving model's 2,197-row training set and the preserved 14,867-row historical-export candidate. Neither new candidate has been promoted into production.

The initial public-route 403 was traced to the ALB's forwarded port 80 reaching Spring while the public scheme was HTTPS. Nginx now sets forwarded port 443 and clears the untrusted `Forwarded` header on API and WebSocket routes. The old-image failure was reproduced; the new image passed HTTPS-origin POST/WS with forwarded-port/spoofed-header inputs, foreign-origin 403, same-account relay, cross-account isolation and stop. The subsequent full public smoke passed. Kakao's JavaScript SDK domain allowlist includes the new HTTPS domain; this configuration check is not a real-device GPS test.

A separate authorized [RAG evaluation of 10 author-written scenarios](../../docs/RAG-EVALUATION-20261104.md) completed through the earlier verified ECS route: all HTTP 200, eight GPT-backed answers and two out-of-scope abstentions without LLM calls.
