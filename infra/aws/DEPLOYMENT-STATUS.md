The API replica count stays at one because live-location relay state is in memory. A separate cycle task consumes SQS once and exits; it is not a continuously running worker service. Its first on-demand execution and S3-to-public-API aggregate refresh succeeded. The hourly worker rule is enabled; an empty queue causes it to exit without a new collection. The separate weekly enqueue rule is also enabled with `cron(0 17 ? * SUN *)`, creating requests at Monday 02:00 KST. The first expected regular consumer opportunity is 02:05 KST, subject to scheduling/capacity delays.

- Observe the first scheduled execution and subsequent failures/retries; a successful initial run and enabled rule do not establish ongoing reliability. A completed cycle must not promote the service model.
