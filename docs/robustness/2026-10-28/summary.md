# 요구사항 견고성 개선 루프

시작점: `8caa18b`의 깨끗한 작업 트리. API 키 없이 차량·이동 계획·주행·백업 기능의 데이터 보존과 비동기 처리 경계를 개선했다. 구현자와 다른 검토자가 교차 검토했고, 사용자가 현재 루프를 마무리하도록 요청한 뒤에는 범위를 추가하지 않았다.

## 범위와 남은 조건

실제 공급자 호출, 실제 API 키, 네이티브 GPS·OS 알림 전달은 사용하지 않았다. 알림 검사는 실제 서비스 코드와 가짜 OS 어댑터를 사용하며 실기기 검증을 대체하지 않는다. Google 재발급 직렬화는 하나의 서버 프로세스 안에서만 보장한다. 다중 worker 운영에는 프로세스 간 lease 또는 전용 토큰 서비스가 필요하다. 공용 서비스 배포·자동 동기화·현대 실차 연동은 이번 변경의 범위가 아니다. 이전에 문서화한 개발 도구 의존성 경고도 별도 잔여 항목이다.

명시적으로 확정한 복원·초기화는 상태가 유지되는 탭 이동만으로 취소하지 않는다. 화면이 해제되거나 계정·주행·현재 데이터가 바뀌면 commit을 차단한다. 알림 취소는 되돌릴 수 없으므로 데이터 교체가 중단된 경우 필요한 알림을 다시 켜도록 안내한다.

## 재현 및 인계

`npm run check`, `npm run check:backend`, `npm run test:integrated`, `npx expo export --platform all`을 사용한다. 실제 HTTP 강제 종료·재시작 검사는 `backend/scripts/verify_restart.py`에 있다. 이 루프의 최종 결과는 [검증 기록](../../VALIDATION.md)과 [상태 파일](state.json)에 기록한다.

이어갈 때: “`docs/robustness/2026-10-28/summary.md`와 `state.json`의 검증 범위를 확인하고, 실제 키는 사용하지 않은 채 새로 재현되는 요구사항 위반만 별도 브랜치에서 수정하라. 운영·실기기 연결은 별도 범위로 다뤄라.”
