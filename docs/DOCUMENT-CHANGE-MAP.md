# DriveMate 원본 자료 위치별 수정표

작성 기준은 2026-11-04다. 아래 네 원본을 직접 읽고 현재 코드와 실행 결과를 대조했다. **원본 Word·PowerPoint·기존 모델링 노트북은 수정하지 않았다.** 이 문서는 팀원이 수정본을 만들 때 사용할 교체 문구와 위치 안내다.

현재 전달 기준은 **로컬 실행 완료·AWS 미배포**다. 온비드 수집·전처리·학습·가격 근거 설명·문서 검색을 구현하고 로컬에서 검증했다. 실패한 AWS 배포의 데이터베이스는 최종 암호화 백업 후 삭제했고, 실패 스택·VPC·빈 작업 큐도 정리했다. 현재 공개 운영 URL·EC2·RDS·주간 자동 작업은 없다. RDS 실제 적재·SQL 검색과 GitHub 원격 CI/CD 성공도 완료로 기재하지 않는다. 이후 성공 기록이 생기면 그 기록을 근거로 해당 상태만 갱신한다.

## 바로 넣을 추가 원고

### A 가격 설명과 프로젝트 문서 검색

가격 설명과 문서 검색을 분리해 구현했다. 가격 설명에서는 Python이 계산한 공매 가격·참고 구간·비용 가정·유사 사례·한계로 근거 카드를 구성하고 GPT가 그중 설명할 항목을 선택한다. 새 가격이나 확인되지 않은 사고·정비 사실을 생성하도록 하지 않았다. 검증에 실패하거나 외부 호출이 실패하면 기본 설명이라는 상태를 표시한다.

프로젝트 문서 검색은 승인된 문서 본문에서 개인정보를 가린 뒤 임베딩했다. 한국어 단어·문자 기반 BM25와 벡터 검색을 결합하고, 원문 절/슬라이드와 출처 상태를 반환한다. GPT를 사용할 때도 검색된 출처 ID만 선택하도록 제한했다. 과거 계획, 당시 보고, 공식 자료, 현재 코드로 확인한 내용을 구분한다. 6개 문서·83개 청크의 작은 개발용 코퍼스이며, 정답 출처 질문 10개와 문서 밖 질문 3개의 확인 결과를 일반적인 정확도·환각 방지 보장으로 해석하지 않는다. Spring HTTP에서 명시적 local 검색과 GPT 응답은 확인했지만 실제 RDS 적재·SQL 검색은 미실행이다.

### B 중간보고서 Abstract 교체 문단

현재 DriveMate는 공식 온비드 공매 자료를 수집해 단일 차량 학습용 2,197행을 정제하고, 시간과 반복 차량 그룹을 구분해 비부스팅 모델을 비교했다. 검증 구간에서 로그가격 Random Forest를 선택했으며, 최종 시험 341건의 평균 절대오차는 236.15만원이었다. 사전 지원 조건에 맞는 262건에서는 134.74만원으로 측정됐고 제공률은 76.83%였다. 사용자는 현재 조건과 6·12개월 보유 가정의 가격·비용을 비교하고, 유사 공매 사례와 유보 이유를 확인할 수 있다. Spring API와 Python 모델·근거 설명·프로젝트 문서 검색을 로컬에서 구현·검증했다. 공매 자료의 대표성, 실제 미래 시장가격, 사용자 이해도는 추가 검증 대상이며 AWS 운영 배포는 완료하지 못했다.

문서 검색은 허용 이메일의 일반 공개 가입만으로 접근할 수 없도록 분리했다. 최초 승인 계정은 관리자 초기화 절차를 사용한다. 로컬에서 최초 토큰 제거·Spring 재시작 후 로그인 200과 예약 이메일 일반 가입 403을 확인했다. AWS에서는 이 절차를 실행하지 못했다. 유료 기능은 UTC 날짜 기준 서버 전체 20개 요청/일 한도를 공유하며, 요청 1회가 OpenAI HTTP 호출 정확히 1회를 의미하지 않는다.

### D 검증 범위 문장

최신 로컬 Spring 검증은 47개 테스트를 통과했다. 프런트는 타입·lint·90개 검사와 웹 export를 통과했고, RAG 단위 테스트 9개를 수행했다. 실제 로컬 HTTP에서는 로그인 200, 예약 이메일 일반 가입 403, ML+GPT 200(7.77초), local RAG+GPT 200·answered(6.71초), 분석 집계 200을 확인했다. 응답 시간은 각 1회 관측이다. 별도로 최신 Colab용 노트북의 코드 9개 셀·내장 테스트 25개를 WSL에서 실행했고, 동일 Drive 파일 갱신과 재다운로드 바이트 일치도 확인했다. 이 결과는 모바일 실기기 검증, 현재 Colab 런타임 실행, 실제 사용자 연구, AWS 정상 운영 또는 GitHub 원격 Actions 실행의 증거는 아니다. 이후 변경이 있으면 `DELIVERY-NOTES.md`의 최신 검증 기록으로 갱신한다.

## GitHub에 올릴 위치와 제외할 것

사용자가 지정한 공개 저장소 **[cloud-project-mobility/make_drive_mate](https://github.com/cloud-project-mobility/make_drive_mate)**의 main에 소스 312개 파일을 업로드했다. 최초 통합 커밋 `8b8eea7484ebe8cf8f2dde10ab0f6737a1d5aa21`의 로컬·원격 일치를 확인했다. 원격 CI 워크플로 등록과 실제 실행 시작을 확인했다. 최종 상태는 [Actions 기록](https://github.com/cloud-project-mobility/make_drive_mate/actions)을 따른다. 기존 `FE-test` 로컬 작업본에서 필요한 소스만 선별했고 원본 Office 문서·원시/정제 데이터·모델·RAG 본문/색인·비밀정보는 제외했다. 현재 AWS 대상 호스트가 없어 CD는 활성화하지 않는다. 이후 변경에도 아래 공개 제외 정책을 유지한다.

| 자료 | 대상 위치 | 전달 방식 |
|---|---|---|
| 화면·도메인·서비스 코드 | `src/`, 관련 테스트 `tests/` | 기존 저장소의 해당 파일 경로를 유지해 검토·반영한다. 다른 팀원 변경은 덮어쓰지 않는다. |
| Spring 서버 | `backend-spring/` | 소스·Maven 설정·테스트·샘플 설정을 올린다. 생성된 `target/`, 실제 계정·DB 비밀번호·인증 토큰은 제외한다. |
| 수집·ML·설명·RAG | `backend/scripts/`, `backend/requirements-ml.txt`, `backend/requirements-rag.txt` | 코드와 테스트·고정 의존성을 올린다. `.env`와 학습 결과 파일은 포함하지 않는다. |
| 분석 반복·AWS·CI/CD 코드 | `infra/aws/`, `.github/workflows/` | 관리자 검토 후 코드만 반영한다. 실제 secret/허용 계정 목록/배포 번들/로컬 상태 파일은 제외한다. 파일 반영과 원격 실행 성공을 구분한다. |
| 기술 설명·수정 지침 | `docs/ONBID-DATA.md`, `ONBID-MODEL.md`, `RAG.md`, `CYCLE.md`, `ARCHITECTURE.md`, `CICD.md`, `DELIVERY-NOTES.md`, `DOCUMENT-CHANGE-MAP.md` | 수치·한계·재현 절차를 담은 개인정보 없는 Markdown을 올린다. 원본 전체 추출 JSON은 올리지 않는다. |
| 새 학습 노트북 코드 | `notebooks/DriveMate_Onbid_Model_Comparison.ipynb`, `notebooks/README.md` | **데이터 없는 코드 전용 사본 생성 완료.** `backend/scripts` 구현을 재사용하고 승인된 원본 자료는 별도 `RAW_RUN_DIR`로 지정한다. 출력·키·내장 원시 레코드는 포함하지 않는다. Git 반영·CI 성공 여부는 원격 기록으로 별도 확인한다. |
| Word·PowerPoint 수정본 | 팀이 승인한 비공개 Drive/OneDrive 제출 폴더 | 개인정보·학사 정보가 있는 원본과 수정본은 기본적으로 Git 커밋 대상에서 제외한다. GitHub에는 내용과 구현의 차이를 설명하는 이 수정표를 남긴다. |
| 실제 데이터·모델·검색 인덱스 | 로컬 `backend/data/`, 승인된 비공개 저장소 | 원본/정제/제외 자료·차량 식별자·joblib·임베딩·문서 원문·실행 결과는 코드 저장소에 커밋하지 않는다. |

**현재 배포용 Colab 노트북에는 실제 원본과 코드 ZIP이 base64로 내장되어 있다.** API 키가 없다는 검사 결과만으로 GitHub에 올려도 되는 것은 아니다. `DriveMate_Onbid_ExtraTrees.ipynb`, `drivemate_colab_bundle.zip`, 결과 ZIP을 그대로 커밋하지 않는다. 키 없는 독립 실행용 공유본과 데이터 없는 코드 검토용 노트북은 목적이 다르다.

반영 전에 변경 파일 목록을 확인해 필요한 소스·테스트·Markdown만 지정한다. 전체 폴더를 한 번에 추가하는 작업은 피한다. 기존 `.gitignore`는 `.env*`와 `backend/data/` 등을 제외하지만, 이미 추적 중인 파일을 자동으로 제거해 주지는 않는다. 기존 `docs/deliverables` 원본은 이번 작업에서 수정·삭제하지 않았으므로 보관 정책 변경은 별도로 결정한다. 계정 권한을 얻었다는 이유만으로 키·개인 문서·학습 원본을 업로드하지 않는다.

## 팀 인수 순서

1. 데이터·모델 담당자는 최신 노트북을 깨끗한 로컬/Colab 환경에서 다시 실행하고 2,197행·선택 모델·전체/조건부 수치가 맞는지 확인한다. Colab 결과는 실제 실행한 뒤 기록한다.
2. 서버·프런트 담당자는 서버 로그인부터 공매 결과·유보·GPT 기본 설명·문서 권한까지 로컬에서 확인한다. 등록 차량·시연 입력과 실제 학습 입력을 혼동하지 않는다.
3. 문서 담당자는 이 표의 Word 절·PPT 번호·기존 노트북 셀을 따라 수정본을 만들고 수치와 날짜를 맞춘다. Word는 목차를 갱신하고, 문서·슬라이드는 실제 렌더링/화면으로 잘림과 배치를 확인한다.
4. 배포 담당자는 [AWS 상태 기록](../infra/aws/DEPLOYMENT-STATUS.md)의 실패 원인·정리 완료·보존 백업·저장 비용을 인수한다. 현재는 신규 AWS 배포를 진행하지 않는 로컬 우선 상태다. 향후 운영 배포·RDS 검색·자동 사이클·원격 CI/CD가 확인되면 해당 증거로 상태를 갱신한다. 아직 완료되지 않은 항목을 발표용 표현으로 먼저 완료 처리하지 않는다.
5. 쓰기 권한이 있는 저장소 담당자는 필요한 코드 변경만 검토·반영하고 CI 실행 결과를 연결한다. 팀원이 개인별 수행 내용과 검토자를 최종 확인한다.
